AWS Core ran HeadObject before and after its denied delete. The fixture existed both times with the same ETag.

Practical use: a company can allow an AI/MCP integration to inspect a large AWS surface while selectively blocking high-risk mutations that would still be available to another approved automation path.

7. What failed — and why that was useful

The first main runs exposed missing Terraform provider read permissions: S3 accelerate/lifecycle reads and EventBridge tag reads. The resource create permissions were not enough because Terraform must refresh existing resource state.

After the narrowly scoped role permissions were corrected, Terraform reconciled the partially created/tainted resources and the complete workflow passed.

Lesson: least privilege for Terraform means “minimum permissions needed for create/update/delete plus provider refresh/readback.”

10. Six things Amit should remember

  1. OIDC replaces stored AWS keys for GitHub CI/CD.
  2. Terraform owns durable state; workflows execute and verify it.
  3. S3 and EventBridge are event producers; Lambda is the worker; DynamoDB is simple evidence.
  4. Verify the final effect, not only that an API returned success.
  5. MCP-origin requests can have stricter IAM controls via aws:ViaAWSMCPService / aws:CalledViaAWSMCP.
  6. Terraform least privilege includes read/refresh APIs, not only provisioning APIs.
