What are we actually proving?

This lab connects GitHub Actions, AWS OIDC, Terraform, ECR, S3, EventBridge, Lambda, DynamoDB, CloudWatch and AWS MCP. The purpose is not to collect services. It is to learn three reusable operating patterns.

Core idea: Git/Terraform owns durable desired state. GitHub Actions gets short-lived AWS credentials with OIDC. AWS MCP is used as an independent operator/verifier and can be given different permissions from the non-MCP CI/CD path.

2. Three experiments, three lessons

CI/CD

📦 ECR artifact flow

GitHub Actions builds a tiny Docker image, pushes it to private ECR, verifies the digest, then deletes the image.

Learn: OIDC can power a real artifact pipeline without AWS access keys stored in GitHub.

Automation

⚡ Event-driven flow

Both S3 and EventBridge trigger one Lambda. Lambda writes deterministic evidence into DynamoDB and logs to CloudWatch.

Learn: producers can change while the automation worker and evidence store stay consistent.

Governance

🛡️ MCP-aware IAM

A protected S3 fixture cannot be deleted when the call arrives through an AWS managed MCP server, but GitHub OIDC can delete equivalent temporary objects.

Learn: IAM can govern the request path, not just the user/role.

5. MCP-aware IAM — why this matters

Request pathProtected S3 deleteWhy
GitHub Actions → OIDC role → S3Allowed for temporary CI/CD cleanupThe request is not routed through AWS MCP.
ChatGPT → AWS Core MCP → S3Denied for the protected fixtureaws:ViaAWSMCPService = true activates an explicit deny.

AWS also provides aws:CalledViaAWSMCP when you want to distinguish the specific managed MCP server, for example aws-mcp.amazonaws.com.

Practical meaning: the same AWS environment can permit ChatGPT to inspect broadly while preventing selected destructive actions specifically when they originate through MCP.

8. Cost and cleanup

Retained

Empty ECR repo, private S3 bucket + one tiny guard object, on-demand DynamoDB table, 128 MB Lambda, one EventBridge rule, 1-day log group, Lambda IAM role.

Deleted after tests

Container images, smoke-test S3 objects and DynamoDB rows.

Safety

No public endpoint. No real data. No static AWS credentials. Narrow names/tags and repo-specific OIDC trust.

9. Five things Amit should remember

  1. OIDC replaces stored AWS keys for GitHub CI/CD.
  2. Terraform owns durable state; workflows prove it works.
  3. EventBridge and S3 are event producers; Lambda is the worker; DynamoDB is simple proof/evidence.
  4. AWS MCP can be independently constrained with MCP-specific IAM context keys.
  5. Good automation tests verify the final effect, not only that an API accepted a request.
